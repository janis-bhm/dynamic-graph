# `find_bridge` crate guide

`find_bridge` implements dynamic bridge finding on top of `top_tree`. All non-test code lives in a single module: `FindBridge` owns a dynamic forest whose edge weights are `EdgeId` handles and whose node weights are per-vertex `VertexLabels`, and it applies the paper's graph-level reduction itself.

The public API is therefore that module's worth of items re-exported from `lib.rs`: `CoverLevel`, `CoverTag`, `FindBridge`, `Level`, `NO_COVER`, and the `VertexId`/`EdgeId` handles.

## Structure

- `src/lib.rs` (114 lines) holds the crate docs — prose plus two doctests that pin the tree/bridge lifecycle and `link`'s covering of an already-connected pair, and are the executable description of the non-tree behaviour — then `mod cover_level;` and one `pub use`.
- `src/cover_level.rs` (1740 lines) holds everything else that is compiled:
  - `PartTree = BTree<i32, PartEntry>` with `SizeVector`, `PartEntry`, and the FindSize helpers (`along_path_find_size`, `off_path_find_size`, `total_sum`, `range_sum`, `restrict`, `diagonal_sum`, ...). `augmented_tree` supplies the aggregated balanced `BTree`.
  - `CoverLevel`, the `top_tree::Summary` impl with `type Tag = CoverTag`; `CoverTag`; `NO_COVER`; `Level` over `-1..=LEVEL_CAP`, with `LEVEL_CAP = 32` and `SLOTS = LEVEL_CAP + 2`.
  - Handles `VertexId(top_tree::ClusterId)` and `EdgeId(NonMaxUsize)`.
  - `FindBridge`, owning `top_tree::TopTree<CoverLevel, VertexLabels, EdgeId>` and `edges: SlotVec<Edge, EdgeId>`.
  - The Appendix A reduction: `add_non_tree_edge`, `find_first_label`, `smallest_label_at`, `first_path`, `find_label_vertex`, `remove_edge`, `swap_edge_for_delete`, `recover`, `find_repalcement` (the typo is in the source; defined in `cover_level.rs` immediately after `recover` and called from `swap_edge_for_delete`), `recover_phase`, `with_path_tag`, `with_vertex_id_path_tag` (the two path taggers: `with_path_tag` is the `VertexId` adapter and is `#[cfg(test)]` like its only callers `cover`/`uncover`, while `with_vertex_id_path_tag` is reached from `link`, `remove_edge` and `recover_phase`).
  - Two `#[cfg(test)]` declarations close the file: `mod tests;` and `mod graph_api;`.
- `FindBridge`'s public methods: `new`, `default`, `add_vertex() -> VertexId` (takes no arguments), `endpoints -> Option<(VertexId, VertexId)>`, `remove_vertex`, `tree_edge_count -> usize`, `link -> EdgeId`, `connected`, `remove_edge`, `cover_level_between -> i32`, `min_covered_edge_between -> Option<EdgeId>`, `find_bridge -> Option<EdgeId>`, `find_bridge_between -> Option<EdgeId>`, `component_size -> u64`, `two_edge_component_size -> u64`. `cover` and `uncover` are **not** on that list: they are private and `#[cfg(test)]`, so they exist only in the crate's own unit-test build, where `tests.rs` and `graph_api/surface.rs` call them to build cover states that no public operation can reach. Nothing outside the test tree refers to them, nor to `with_path_tag`, the `VertexId` adapter whose only callers they are — all three are `#[cfg(test)]`, which is why a plain `--lib` build reports no dead code here. There is no `edge_count`: `tree_edge_count` counts forest edges only, and a live-edge count lives on the test driver's `Graph`. The public items with no doc comment are `VertexId::index` and `EdgeId::index`.
- The test tree hangs off the two `#[cfg(test)]` modules:
  - `src/cover_level/tests.rs` — the original unit suite, **44 tests** (one of them `#[ignore]`d): `SizeVector`/`PartTree` internals, `link`, `cover`/`uncover`, `find_first_label`, `find_size_internal`, the level-cap edge cases, and the `remove_edge`/`recover_phase` cases. Its `Naive` oracle is a simple graph (`BTreeMap<usize, BTreeSet<usize>>`) with no multiplicities and no bridge analysis; it also defines a local `Rng`.
  - `src/cover_level/graph_api.rs` — the differential foundation, plus one smoke test (`graph_level_triangle_through_the_driver`): a `Naive` *multigraph* oracle with real bridge analysis (`is_bridge`, `bridges`, `bridge_pairs`, `two_edge_connected`, `two_edge_component_size`, `bridge_separating`, `bridge_in_component`, `component_labels`), a `Graph` driver that emulates Appendix A `Insert`/`Delete` on top of the `FindBridge` API, and the assertion helpers `assert_matches_naive`, `assert_internal_invariants`, `assert_bookkeeping`, `assert_endpoints_match`, `assert_returned_bridge_in_component`, `assert_returned_separating_bridge`, `pairs`. Its `insert` is a thin pass-through to `FindBridge::link`, because `link` completes both branches of Appendix A's `Insert`.
  - `src/cover_level/graph_api/fixed.rs` — **19 tests**: deterministic hand-built shapes (triangle, parallel edges, trees, disconnected components, a K4 deletion, vertex removal) and a four-fixture oracle table. Ported from the crate's pre-existing graph-module suite.
  - `src/cover_level/graph_api/randomized.rs` — **2 tests**: randomized differential runs, 6 seeds × 180 steps (three seeds per test), with a `Coverage` counter that fails a run that stops reaching `Swap`/`Recover`, plain cuts, non-tree deletion, parallel edges or bridgeless states.
  - `src/cover_level/graph_api/surface.rs` — **16 tests**: public-API contract tests, with the reach the public API lacks supplied by the crate-private `cover`/`uncover` — see *Tests*.
- `top_tree` supplies the forest and summary callbacks; it needs nightly (`#![feature(pattern_types, pattern_type_macro, structural_match)]` in `crates/top_tree/src/lib.rs`).

## Important constraints and maintenance notes

- `link` covers the path itself. On an already-connected pair it covers the tree path between the endpoints at level `0` first, then records a level-0 non-tree edge and returns that handle; a caller never raises or lowers a cover level, because cover levels are bookkeeping `link` and `remove_edge` maintain between them. That is the whole of Appendix A's `Insert`: the paper's `Connect(v, w)` branch condition is evaluated inside `link`, so both branches are already complete when `link` returns. The invariant is what matters, not who applies it: a cycle whose tree path is left uncovered is a graph in which every edge of the cycle still answers as a bridge.
- `EdgeId` slots are recycled. `FindBridge::link` allocates handles from a `SlotVec` whose freed slots are reused, so a stale handle may name a different, live edge after another insertion. Use `FindBridge::endpoints` as the liveness signal: it returns `None` for a free or never-issued slot. The test driver keeps its own `EdgeId -> oracle edge` map because bridge queries return a bare `Option<EdgeId>`.
- `remove_edge` is Appendix A's `Delete`: it cuts an uncovered bridge, or runs `Swap` and then uncovers/`Recover`s a covered tree edge, or drops a non-tree record's labels and uncovers its path. A self-record is label-only, so deletion drops its labels without attempting to cover, uncover, or recover a nonexistent path. `graph_api/surface.rs::remove_edge_on_a_covered_tree_edge_runs_the_swap_and_recover_reduction` pins the covered-tree case.
- `Level` spans `-1..=32`; `NO_COVER` is the separate sentinel above every real level. The dense `SizeVector`s and the `u64` incident masks are sized to that fixed cap, and `Level::increment` is `None` at the cap, so `recover_phase` stops promoting there. See *Known limitations*.
- `FindBridge` attaches exactly one label leaf per vertex in `add_vertex`; that leaf's `top_tree::ClusterId` is the stable identity wrapped by `VertexId`. Internal `top_tree::VertexId`/`EdgeId` are compaction-sensitive and must be re-resolved through the private `vertex_cluster`/`cluster_vertex` after a removal. `top_tree::Summary` requires only `tree_edge`, `label`, `combine`, `flip`, `apply`, and `compose` — there is no `remap_vertex`, so nothing remaps cluster data for you.
- `find_bridge` and `find_bridge_between` return a single `Option<EdgeId>`, not a vertex pair; `link` returns the new `EdgeId`. `endpoints` returns `None` for a handle whose slot is free, no endpoint order is promised for a tree edge (`graph_api/surface.rs` compares the pair as unordered), but a non-tree record does report the orientation of the `link` that created it.
- `remove_vertex` is only valid for a vertex with no incident forest edge and panics otherwise; remove those edges first. A live non-tree record does not trigger the panic: its record and labels are removed from both endpoints. `graph_api/surface.rs::remove_vertex_removes_a_non_tree_record_from_both_endpoints` pins the survivor's clean labels and incident mask.
- `CoverLevel`'s `combine`, `flip`, `apply`, and `compose` must agree with `top_tree::Summary` semantics. Boundary-indexed `PartTree` entries must follow the logical boundary order when a cluster flips; tags must affect path children only.
- The Section 5/6 entry points are private: `find_size_internal`, `find_first_label`, `smallest_label_at`, `first_path`, `find_label_vertex`. Only `component_size` and `two_edge_component_size` are public, and there is no public label add/remove operation on `FindBridge`.

## Known limitations

- The level cap bounds the vertex count. `LEVEL_CAP` is a fixed `32`, so the dense `FindSize`/`FindFirstLabel` structures represent only levels `-1..=32`, and the structure is guaranteed correct only for graphs with fewer than `2^31` vertices. The paper (Section 2) keeps an explicit level per edge bounded by `l_max`, the level whose edges form the spanning forest, where `l_max = Θ(log n)`. The extracted paper text renders the rounding as a bare `` `max = blog2 nc `` — the brackets are lost in extraction — so it does not say whether the paper means `⌊log₂ n⌋` or `⌈log₂ n⌉`, and this guide does not guess. The vertex bound holds either way: `l_max` has to stay strictly below the fixed `LEVEL_CAP = 32`, i.e. at most `31`, which at worst needs `log₂ n < 31`, and below `2^31` vertices both roundings keep `l_max` at `31` or under. A non-tree edge is inserted at level `0` and Appendix A's `Swap`/`RecoverPhase` promote it towards `l_max`, so past that bound a promotion needs a level the dense vectors cannot represent: `Level::increment` is `None`, `recover_phase` falls back to covering at the current level and returns no candidate, and the size invariant that guarantees a replacement edge (`FindReplacement` descending into the side with the smaller level-`i` `FindSize`, `RecoverPhase` promoting only a candidate whose level-`i+1` size fits inside the size budget it was handed) stops holding. The failure surfaces as the `expect("edge was covered, and is now cut")` in `swap_edge_for_delete`. Changing the bound means revisiting the level representation and the promotion logic together.

## Paper references

The primary reference is [*Dynamic Bridge-Finding in O(log² n) Amortized Time* by Holm, Rotenberg, and Thorup (2017)](../../papers/Dynamic%20Bridge-Finding%20in%20O%28log2%20n%29%20Amortized%20Time%20%28holm%2Crotenberg%2Cthorup%29.txt):

- Section 2 gives the dynamic-tree operation interface and the level/cover invariants, including the `l_max = Θ(log n)` bound on edge levels. Its `⌊⌋`/`⌈⌉` rounding is not legible in the extracted text and is not relied on anywhere in this crate (see *Known limitations*).
- Section 4 is `CoverLevel`/`CoverTag`.
- Section 5 is `FindSize`: `along_path_find_size`, `off_path_find_size`, `find_size_internal`.
- Section 6 is `FindFirstLabel`: `add_non_tree_edge`, `find_first_label`, `smallest_label_at`, `first_path`, `find_label_vertex`.
- Appendix A is the graph-level `Insert`, `Delete`, `Swap`, `FindReplacement`, `Recover`, `RecoverPhase` reduction. It all lives inside `impl FindBridge` in `cover_level.rs` — only `Delete`, spelled `remove_edge`, is public; `link` is the public half of `Insert` and `add_non_tree_edge`, `find_first_label`, `swap_edge_for_delete`, `recover`, `find_repalcement` and `recover_phase` are not. There is no graph-level wrapper type in this crate.

Use those sections for the algorithmic invariants, but check the Rust before attributing the paper's full asymptotic bounds to a code path: this implementation has a fixed level cap and exact `u64` size vectors.

## Tests

82 lib tests — 81 run by default and 1 `#[ignore]`d — plus 2 doctests, all passing:

- `cargo test -p find_bridge --lib` — 82 tests: 44 in `cover_level::tests`, 1 in `cover_level::graph_api`, 19 in `cover_level::graph_api::fixed`, 2 in `cover_level::graph_api::randomized`, 16 in `cover_level::graph_api::surface`. `cover_level::tests::randomized_cover_uncover` carries `#[ignore = "this test is slow; run it manually"]`, so the default run reports 81 passed / 1 ignored; it does pass when asked for with `cargo test -p find_bridge --lib -- --ignored` (or `-- --include-ignored`).
- `cargo test -p find_bridge` — the same 81 plus 1 ignored plus the 2 `lib.rs` doctests.
- `cargo test -p top_tree` — 24 tests plus 1 doctest.
- One module at a time: `cargo test -p find_bridge --lib -- cover_level::tests`, `... -- cover_level::graph_api::fixed`, `... -- cover_level::graph_api::randomized`, `... -- cover_level::graph_api::surface`. The randomized suite prints its `Coverage` counters to stderr, so add `-- --nocapture` to see them.
- `cargo test -p find_bridge --doc` — the 2 `lib.rs` doctests, which must compile against the public API alone, so they may not touch the private `cover`/`uncover`.
- `cargo clippy -p find_bridge --all-targets` must not error — it is a deny-by-default gate, so a single lint in the test tree fails the build. The warnings it currently emits are pre-existing and out of scope for changes in this crate: 8 in `cover_level/tests.rs`, 5 in `top_tree/src/tree/mod.rs`, and the `unused manifest key: workspace.edition` manifest warning. `cover_level.rs` itself contributes none: `cover`, `uncover` and `with_path_tag` are `#[cfg(test)]`, so the dead-code warning the `--lib` build used to raise is gone.

The two halves cover different things. `cover_level::tests` pins the internals one unit at a time against a simple-graph oracle with no bridge analysis; it reaches `EdgeId` endpoints through the private `edges: SlotVec` and exercises self-record labels. `graph_api` compares whole snapshots against a multigraph oracle with real bridge analysis, through the `Graph` driver, and its child modules split by intent: `fixed.rs` for named deterministic shapes, `randomized.rs` for aggregate reach, `surface.rs` for the documented contracts — `endpoints` (live, dead, unissued, and after an unrelated vertex removal), `min_covered_edge_between`'s "attains the path minimum" promise and its `None` cases, `cover_level_between` on degenerate inputs, `Level::increment` boundaries, `CoverTag` construction and composition, `FindBridge::default`, the two handle index spaces, queries on an isolated vertex, and graph-level edge removal. Because there is no public way to raise or lower a cover level, `surface.rs` also reaches for the crate-private `cover`/`uncover` to build the states it then pins (`cover_and_uncover_at_level_max` is the level-cap case, and `min_covered_edge_between_attains_the_path_minimum` drives `fb.cover` alongside a hand-rolled `PathModel` of its own). That file is therefore not a pure public-API suite despite its name.
