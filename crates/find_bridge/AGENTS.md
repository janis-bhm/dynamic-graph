# `find_bridge` crate guide

`find_bridge` implements dynamic bridge finding on top of `top_tree`. All non-test code lives in a single module: `FindBridge` owns a dynamic forest whose edge weights are `EdgeId` handles and whose node weights are per-vertex `VertexLabels`, and it applies the paper's graph-level reduction itself.

The public API is therefore that module's worth of items re-exported from `lib.rs`: `CoverLevel`, `CoverTag`, `FindBridge`, `Level`, `NO_COVER`, `UserLabel`, and the `VertexId`/`EdgeId` handles.

## Structure

- `src/lib.rs` (89 lines) holds the crate docs — prose plus two doctests, the latter being the only executable description of `link`'s non-tree behaviour — then `mod cover_level;` and one `pub use`.
- `src/cover_level.rs` (1748 lines) holds everything else that is compiled:
  - `PartTree = BTree<i32, PartEntry>` with `SizeVector`, `PartEntry`, and the FindSize helpers (`along_path_find_size`, `off_path_find_size`, `total_sum`, `range_sum`, `restrict`, `diagonal_sum`, ...). `augmented_tree` supplies the aggregated balanced `BTree`.
  - `CoverLevel`, the `top_tree::Summary` impl with `type Tag = CoverTag`; `CoverTag`; `NO_COVER`; `Level` over `-1..=LEVEL_CAP`, with `LEVEL_CAP = 32` and `SLOTS = LEVEL_CAP + 2`.
  - Handles `VertexId(top_tree::ClusterId)`, `EdgeId(NonMaxUsize)`, `UserLabel(NonMaxUsize)`.
  - `FindBridge`, owning `top_tree::TopTree<CoverLevel, VertexLabels, EdgeId>` and `edges: SlotVec<Edge, EdgeId>`.
  - The Appendix A reduction: `add_non_tree_edge`, `find_first_label`, `smallest_label_at`, `first_path`, `find_label_vertex`, `remove_edge`, `swap_edge_for_delete`, `recover`, `find_repalcement` (the typo is in the source; defined in `cover_level.rs` immediately after `recover` and called from `swap_edge_for_delete`), `recover_phase`, `with_path_tag`, `with_vertex_id_path_tag`.
  - Two `#[cfg(test)]` declarations close the file: `mod tests;` and `mod graph_api;`.
- `FindBridge`'s public methods: `new`, `default`, `add_vertex() -> VertexId` (takes no arguments), `endpoints -> Option<(VertexId, VertexId)>`, `remove_vertex`, `tree_edge_count -> usize`, `link -> EdgeId`, `cut_edge -> bool`, `connected`, `remove_edge`, `cover`, `uncover`, `cover_level_between -> i32`, `min_covered_edge_between -> Option<EdgeId>`, `find_bridge -> Option<EdgeId>`, `find_bridge_between -> Option<EdgeId>`, `component_size -> u64`, `two_edge_component_size -> u64`. There is no `edge_count`: `tree_edge_count` counts forest edges only, and a live-edge count lives on the test driver's `Graph`. The public items with no doc comment are `remove_edge`, `component_size`, `two_edge_component_size`, `VertexId::index` and `EdgeId::index`.
- The test tree hangs off the two `#[cfg(test)]` modules:
  - `src/cover_level/tests.rs` — the original unit suite, **45 tests**: `SizeVector`/`PartTree` internals, `link`/`cut_edge`, `cover`/`uncover`, `find_first_label`, `find_size_internal`, the level-cap edge cases, and the `remove_edge`/`recover_phase` cases. Its `Naive` oracle is a simple graph (`BTreeMap<usize, BTreeSet<usize>>`) with no multiplicities and no bridge analysis; it also defines a local `Rng`.
  - `src/cover_level/graph_api.rs` — the differential foundation, plus one smoke test (`graph_level_triangle_through_the_driver`): a `Naive` *multigraph* oracle with real bridge analysis (`is_bridge`, `bridges`, `bridge_pairs`, `two_edge_connected`, `two_edge_component_size`, `bridge_separating`, `bridge_in_component`, `component_labels`), a `Graph` driver that emulates Appendix A `Insert`/`Delete` on top of the public API, and the assertion helpers `assert_matches_naive`, `assert_internal_invariants`, `assert_bookkeeping`, `assert_endpoints_match`, `assert_returned_bridge_in_component`, `assert_returned_separating_bridge`, `pairs`.
  - `src/cover_level/graph_api/fixed.rs` — **19 tests**: deterministic hand-built shapes (triangle, parallel edges, trees, disconnected components, a K4 deletion, vertex removal) and a four-fixture oracle table. Ported from the crate's pre-existing graph-module suite.
  - `src/cover_level/graph_api/randomized.rs` — **2 tests**: randomized differential runs, 6 seeds × 180 steps, with a `Coverage` counter that fails a run that stops reaching `Swap`/`Recover`, plain cuts, non-tree deletion, parallel edges or bridgeless states.
  - `src/cover_level/graph_api/surface.rs` — **18 tests**: public-API contract tests — see *Tests*.
- `top_tree` supplies the forest and summary callbacks; it needs nightly (`#![feature(pattern_types, pattern_type_macro, structural_match)]` in `crates/top_tree/src/lib.rs`).

## Important constraints and maintenance notes

- `link` does not cover. On an already-connected pair it records a level-0 non-tree edge and returns that handle, but it does **not** raise the cover level of the tree path between the endpoints; the caller must `cover` that path itself. This is Appendix A's `Insert`, where the `Connect(v, w)` test is the branch condition, so connectivity has to be sampled *before* the `link` — which is exactly why `graph_api::Graph::insert` does it in that order. Getting this wrong yields a graph with a real cycle whose edges all still answer as bridges.
- `EdgeId` slots are recycled. `FindBridge::link` allocates handles from a `SlotVec` whose freed slots are reused, so a handle from a deleted edge may name a different, live edge afterwards: never hold a deleted handle and assume it is dead, and never expect `delete`/`cut_edge` to report "nothing was there" for it. `cut_edge` answers `false` only while the slot is genuinely free (see `graph_api/fixed.rs::delete_twice_returns_false` for the case that checks the slot first). Since `find_bridge`/`find_bridge_between` return a bare `Option<EdgeId>`, liveness has to be checked against bookkeeping outside `FindBridge` — the test driver keeps its own `EdgeId -> oracle edge` map for that.
- `cut_edge` is a forest operation, not the graph-level delete. On a tree edge it only splits the forest: it runs neither `Swap` nor `Recover`, so cover levels and non-tree labels keep describing the pre-cut path. `remove_edge` is Appendix A's `Delete` — cut a bridge, or `Swap` and then uncover/`Recover` a covered tree edge, or drop a non-tree edge's labels and uncover its path. `graph_api/surface.rs` pins both behaviours (`cut_edge_on_a_covered_tree_edge_only_splits_the_forest`, `remove_edge_on_a_covered_tree_edge_runs_the_swap_and_recover_reduction`).
- `Level` spans `-1..=32`; `NO_COVER` is the separate sentinel above every real level. The dense `SizeVector`s and the `u64` incident masks are sized to that fixed cap, and `Level::increment` is `None` at the cap, so `recover_phase` stops promoting there. See *Known limitations*.
- `FindBridge` attaches exactly one label leaf per vertex in `add_vertex`; that leaf's `top_tree::ClusterId` is the stable identity wrapped by `VertexId`. Internal `top_tree::VertexId`/`EdgeId` are compaction-sensitive and must be re-resolved through the private `vertex_cluster`/`cluster_vertex` after a removal. `top_tree::Summary` requires only `tree_edge`, `label`, `combine`, `flip`, `apply`, and `compose` — there is no `remap_vertex`, so nothing remaps cluster data for you.
- `find_bridge` and `find_bridge_between` return a single `Option<EdgeId>`, not a vertex pair; `link` returns the new `EdgeId`. `endpoints` returns `None` for a handle whose slot is free, and no endpoint order is promised for a tree edge (`graph_api/surface.rs` compares the pair as unordered).
- `remove_vertex` is only valid for a vertex with no incident forest edge and panics otherwise; cut or remove those edges first. A live non-tree record does *not* trigger the panic, but its slot is dropped while the other endpoint keeps a dangling label naming the dead handle — a **known defect**, not a contract (`remove_vertex`'s own doc says it removes labels attached to the removed vertex and says nothing about the other endpoint). It is harmless for the public queries; `graph_api/surface.rs::remove_vertex_leaves_a_dangling_label_at_the_other_endpoint` characterises it, and the `KNOWN DEFECT` block inside that test (findable with `grep -n 'KNOWN DEFECT'`) is deleted — and nothing else — once `remove_vertex` drops the record from both endpoints.
- `CoverLevel`'s `combine`, `flip`, `apply`, and `compose` must agree with `top_tree::Summary` semantics. Boundary-indexed `PartTree` entries must follow the logical boundary order when a cluster flips; tags must affect path children only.
- The Section 5/6 entry points are private: `find_size_internal`, `find_first_label`, `smallest_label_at`, `first_path`, `find_label_vertex`. Only `component_size` and `two_edge_component_size` are public, and there is no public label add/remove operation on `FindBridge`.

## Known limitations

- The level cap bounds the vertex count. `LEVEL_CAP` is a fixed `32`, so the dense `FindSize`/`FindFirstLabel` structures represent only levels `-1..=32`, and the structure is guaranteed correct only for graphs with fewer than `2^31` vertices. The paper (Section 2) keeps an explicit level per edge bounded by `l_max`, the level whose edges form the spanning forest, where `l_max = Θ(log n)`. The extracted paper text renders the rounding as a bare `` `max = blog2 nc `` — the brackets are lost in extraction — so it does not say whether the paper means `⌊log₂ n⌋` or `⌈log₂ n⌉`, and this guide does not guess. The vertex bound holds either way: `l_max` has to stay strictly below the fixed `LEVEL_CAP = 32`, i.e. at most `31`, which at worst needs `log₂ n < 31`, and below `2^31` vertices both roundings keep `l_max` at `31` or under. A non-tree edge is inserted at level `0` and Appendix A's `Swap`/`RecoverPhase` promote it towards `l_max`, so past that bound a promotion needs a level the dense vectors cannot represent: `Level::increment` is `None`, `recover_phase` falls back to covering at the current level and returns no candidate, and the size invariant that guarantees a replacement edge (`FindReplacement` descending into the side with the smaller level-`i` `FindSize`, `RecoverPhase` promoting only a candidate whose level-`i+1` size fits inside the size budget it was handed) stops holding. The failure surfaces as the `expect("edge was covered, and is now cut")` in `swap_edge_for_delete`. Changing the bound means revisiting the level representation and the promotion logic together.
- `UserLabel` is re-exported but unreachable: no public `FindBridge` operation takes or returns one. Labels in this implementation are non-tree edges, addressed by `EdgeId`. It is `pub struct UserLabel(pub NonMaxUsize)`, so the payload is public and readable — it is not opaque, and it carries no `repr` attribute, so nothing depends on its layout. `graph_api/surface.rs::user_label_is_a_public_newtype_handle` pins only the public field, the derives and the type's identity/order behaviour; whether to delete it is an open question.

## Paper references

The primary reference is [*Dynamic Bridge-Finding in O(log² n) Amortized Time* by Holm, Rotenberg, and Thorup (2017)](../../papers/Dynamic%20Bridge-Finding%20in%20O%28log2%20n%29%20Amortized%20Time%20%28holm%2Crotenberg%2Cthorup%29.txt):

- Section 2 gives the dynamic-tree operation interface and the level/cover invariants, including the `l_max = Θ(log n)` bound on edge levels. Its `⌊⌋`/`⌈⌉` rounding is not legible in the extracted text and is not relied on anywhere in this crate (see *Known limitations*).
- Section 4 is `CoverLevel`/`CoverTag`.
- Section 5 is `FindSize`: `along_path_find_size`, `off_path_find_size`, `find_size_internal`.
- Section 6 is `FindFirstLabel`: `add_non_tree_edge`, `find_first_label`, `smallest_label_at`, `first_path`, `find_label_vertex`.
- Appendix A is the graph-level `Insert`, `Delete`, `Swap`, `FindReplacement`, `Recover`, `RecoverPhase` reduction. All of it is private inside `impl FindBridge` in `cover_level.rs`; there is no graph-level wrapper type in this crate.

Use those sections for the algorithmic invariants, but check the Rust before attributing the paper's full asymptotic bounds to a code path: this implementation has a fixed level cap and exact `u64` size vectors.

## Tests

85 lib tests plus 2 doctests, all passing:

- `cargo test -p find_bridge --lib` — 85 tests: 45 in `cover_level::tests`, 1 in `cover_level::graph_api`, 19 in `cover_level::graph_api::fixed`, 2 in `cover_level::graph_api::randomized`, 18 in `cover_level::graph_api::surface`.
- `cargo test -p find_bridge` — the same 85 plus the 2 `lib.rs` doctests.
- `cargo test -p top_tree` — 24 tests plus 1 doctest.
- One module at a time: `cargo test -p find_bridge --lib -- cover_level::tests`, `... -- cover_level::graph_api::fixed`, `... -- cover_level::graph_api::randomized`, `... -- cover_level::graph_api::surface`. The randomized suite prints its `Coverage` counters to stderr, so add `-- --nocapture` to see them.
- `cargo clippy -p find_bridge --all-targets` must not error — it is a deny-by-default gate, so a single lint in the test tree fails the build. The warnings it does currently emit are pre-existing and out of scope for changes in this crate: 8 in `cover_level/tests.rs`, 5 in `top_tree/src/tree/mod.rs`, and the `unused manifest key: workspace.edition` manifest warning.

The two halves cover different things. `cover_level::tests` pins the internals one unit at a time against a simple-graph oracle with no bridge analysis; it reaches `EdgeId` endpoints through the private `edges: SlotVec` rather than through `FindBridge::endpoints`, which is why that method had no coverage at all until `surface.rs`. `graph_api` compares whole snapshots against a multigraph oracle with real bridge analysis, through the `Graph` driver, and its child modules split by intent: `fixed.rs` for named deterministic shapes, `randomized.rs` for aggregate reach, `surface.rs` for the documented contracts — `endpoints` (live, dead, unissued, and after an unrelated vertex removal), `min_covered_edge_between`'s "attains the path minimum" promise and its `None` cases, `cover_level_between` on degenerate inputs, `Level::increment` boundaries, `CoverTag` construction and composition, `FindBridge::default`, the two handle index spaces, and the `cut_edge` vs `remove_edge` contrast.
